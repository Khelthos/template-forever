# Azeroth Guild Template

[English](../../README.md) · [Deutsch](../de/README.md) · [Français](../fr/README.md) · [Español](../es/README.md) · [Italiano](../it/README.md) · [Português (Brasil)](../pt-BR/README.md) · **Русский** · [한국어](../ko/README.md) · [简体中文](../zh-CN/README.md) · [繁體中文](../zh-TW/README.md)

**Бесплатный статический** шаблон сайта для гильдий **World of Warcraft: Forever**. Сделайте форк, отредактируйте один файл настроек, пишите новости и руководства в Markdown и публикуйте сайт бесплатно на GitHub Pages.

Создан на [Astro](https://astro.build), [Tailwind CSS 4](https://tailwindcss.com) и чистом JavaScript. Без сервера, без базы данных, без платных сервисов.

> Проект сообщества, не связан с Blizzard Entertainment и не одобрен ею.

## Возможности

- **Облик Альянса или Орды:** эмблемы, иллюстрация на главной, герб и палитра меняются вместе с фракцией.
- **10 языков интерфейса** — те, на которые переведена World of Warcraft: English, Deutsch, Français, Español, Italiano, Português (Brasil), Русский, 한국어, 简体中文, 繁體中文.
- **12 палитр** (2 фракционные и 10 по мотивам рас Forever) или собственные цвета в HEX; контрастность автоматически проверяется в светлой и тёмной темах.
- **5 бесплатных наборов шрифтов** (Google Fonts, лицензия OFL), которые скачиваются во время сборки: посетители не отправляют запросов в Google.
- **Главная страница** с обложкой, описанием, набором, активностями, последними новостями, составом и руководствами.
- **Страница «О гильдии»**: история, ценности, структура, требования, статус набора и контакты.
- **Новости в Markdown**: категории, теги, обложки, черновики, постраничная навигация и похожие статьи.
- **Руководства в Markdown**: категории, рекомендуемые материалы, автоматическое содержание, теги и похожие руководства.
- **Состав гильдии** из JSON-файла с поиском, фильтрами (раса, класс, специализация, роль, звание, статус) и сортировкой.
- **Поиск** по новостям и руководствам полностью в браузере.
- **Светлая и тёмная темы**, доступное мобильное меню, управление с клавиатуры; сайт работает без JavaScript.
- **SEO:** канонические URL, Open Graph, sitemap, robots.txt, правильный базовый путь на GitHub Pages.
- **Автоматические проверки** настроек, материалов, ссылок и указания авторства, а также автотесты.

## Быстрый старт

Требуется [Node.js](https://nodejs.org) 22.23 или новее (рекомендуется 24) и Git.

```bash
git clone https://github.com/<ваш-пользователь>/<ваш-репозиторий>.git
cd <ваш-репозиторий>
npm ci
npm run dev
```

Откройте адрес, указанный в терминале (обычно `http://localhost:4321/<имя-репозитория>/`).

## Настройка сайта

| Что | Где |
| --- | --- |
| Название, фракция, язык, цвета, шрифты, разделы, соцсети | `src/config/site.config.mjs` |
| Текст страницы «О гильдии» | `src/content/pages/about.md` |
| Новости | `src/content/news/*.md` |
| Руководства | `src/content/guides/*.md` |
| Состав | `src/data/roster.json` |
| Логотип, фоны, изображения | `public/images/` |
| Расы, классы, специализации | `src/data/game-data.json` ([источники и статус, на английском](../GAME-DATA.md)) |

После каждого изменения проверяйте всё командами `npm run check:config` и `npm run check:content`.

### 1. Настройки

Откройте `src/config/site.config.mjs`: у каждого поля есть комментарий (на английском; в этом руководстве все параметры описаны по-русски). Например, для гильдии Орды с русским интерфейсом:

```js
site: { language: "ru", /* ... */ },
guild: { faction: "horde", preferredRace: "orc", /* ... */ },
appearance: { colorPreset: "orc", fontPreset: "horde-war", /* ... */ },
```

Ошибочные значения не ломают сайт: они заменяются допустимыми, а `npm run check:config` называет поле, которое нужно исправить.

#### Язык

`site.language` переводит интерфейс: меню, кнопки, подписи, фильтры состава, поиск, даты. Доступные коды: `en`, `de`, `fr`, `es`, `it`, `pt-BR`, `ru`, `ko`, `zh-CN`, `zh-TW`.

Ваши материалы (новости, руководства, страница «О гильдии», тексты в настройках — девиз, активности, названия категорий руководств) показываются ровно так, как вы их написали: пишите их на языке сайта. Демонстрационные материалы написаны на английском.

Для корейского и китайского сайт использует системные шрифты посетителя для иероглифов. Для русского шрифты основного текста поддерживают кириллицу, а декоративные шрифты заголовков для кириллических букв заменяются системным шрифтом с засечками.

#### Справочник настроек

**`site`**

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `name` | `"My Guild"` | Название гильдии (шапка, заголовки, подвал). |
| `shortName` | = `name` | Короткое название для шапки на телефонах. |
| `tagline` | `""` | Девиз на обложке. |
| `description` | `""` | Мета-описание и превью в соцсетях (рекомендуется не более 160 символов). |
| `language` | `"en"` | Язык интерфейса (см. выше). |
| `locale` | по языку | Формат дат, например `"ru-RU"`. |
| `url` | — | Публичный адрес с `/` на конце. **Обязателен и должен быть корректным**, иначе сборка остановится. На GitHub Actions подставляется автоматически. |
| `logo` | герб фракции | Путь в `public/` или https-URL. Пусто = `crest-alliance.svg` / `crest-horde.svg`. |
| `favicon` | `"/favicon.svg"` | Значок вкладки браузера. |
| `ogImage` | логотип | Картинка для превью в соцсетях (1200×630). |

**`guild`**

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `faction` | `"alliance"` | `"alliance"` или `"horde"`: эмблемы, иллюстрация, герб и палитра по умолчанию. |
| `preferredRace` | `""` | Идентификатор расы из игрового каталога. Фракцию не меняет. |
| `server`, `region`, `founded` | `""` | Показываются на главной и на странице «О гильдии», если заполнены. |
| `description` | `""` | Краткое описание (обложка и главная). |
| `ranks` | `["Guild Master","Officer","Member"]` | Звания от старшего к младшему. Состав должен использовать эти названия. |
| `recruitment.status` | `"open"` | `"open"`, `"limited"` или `"closed"`. |
| `recruitment.message` | `""` | Текст блока о наборе. |
| `recruitment.wanted` | `[]` | Нужные классы или роли (свободный текст). |
| `recruitment.contactUrl` | `""` | Ссылка для заявки. Пусто = ссылка на Discord; если её нет — контакты на странице «О гильдии». |
| `activities` | `[]` | `{ title, description, schedule }`. |
| `goals` | `[]` | Список целей. |
| `social.discord`, `.website`, `.youtube`, `.twitch` | `""` | Ссылки https. Пустые или некорректные = кнопка скрыта. |

**`appearance`**

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `theme` | `"dark"` | Начальная тема: `"dark"`, `"light"` или `"system"`. Посетители могут переключать её, если включено `features.themeToggle`. |
| `colorPreset` | фракция | `"alliance"`, `"horde"`, `"faction"`, идентификатор расы (`"human"`, `"dwarf"`, `"night-elf"`, `"gnome"`, `"high-order-skyborne"`, `"orc"`, `"undead"`, `"tauren"`, `"troll"`, `"windshaper-skyborne"`) или `"custom"`. |
| `customColors` | цвета фракции | `{ primary, accent, background }` в HEX, используются с `"custom"`. Контраст исправляется автоматически. |
| `fontPreset` | `"alliance-classic"` | `"alliance-classic"`, `"horde-war"`, `"arcane"`, `"medieval"`, `"clean"`. |
| `fontLoading` | `"self-hosted"` | См. ниже. |
| `backgroundImage` | `""` | Картинка обложки. Пусто = встроенная иллюстрация в цветах палитры. |
| `showAnimations` | `true` | Лёгкая анимация; всегда отключается при `prefers-reduced-motion`. |

**`features`**: `news`, `roster`, `guides`, `recruitment`, `socialLinks`, `themeToggle`, `search` — по умолчанию все `true`. При `false` раздел не создаёт ни страниц, ни ссылок.

**Прочее:** `news.perPage` (новостей на странице архива, 1–50, по умолчанию 6) · `guides.categories` (`{ id, label }`; `id` указывается в поле `type` руководств) · `footer.links` (дополнительные ссылки `{ label, url }`) · `footer.attributionNote` (дополнительный текст рядом с указанием авторства, которое всегда остаётся видимым).

#### Шрифты: на своём сайте или через Google Fonts

| Режим | Как работает | Конфиденциальность |
| --- | --- | --- |
| `"self-hosted"` | [Fonts API в Astro](https://docs.astro.build/en/guides/fonts/) **во время сборки** скачивает из Google Fonts только шрифты выбранного набора и публикует их вместе с сайтом. Для сборки нужен интернет. | Посетители не обращаются к Google. |
| `"google"` | Браузер загружает шрифты с `fonts.googleapis.com`. | Google получает IP-адрес посетителя. |
| `"system"` | Только системные шрифты. | Никаких внешних запросов. |

Используемые семейства: Cinzel, Cinzel Decorative, Grenze, MedievalSharp, Alegreya, Lora, Inter, Source Sans 3 — все бесплатны по лицензии SIL Open Font License.

#### Палитры

Каждая палитра в `src/data/palettes.mjs` задаёт три базовых цвета. Фоны, текст, рамки, обводка фокуса и светлая тема рассчитываются в `src/lib/color.mjs` с минимальным контрастом (текст 7:1, второстепенный текст и ссылки 4,5:1, фокус 3:1). Тест проверяет каждую палитру в обеих темах. Чтобы добавить палитру, достаточно добавить запись — компоненты менять не нужно.

### 2. Логотип и изображения

- **Логотип:** скопируйте файл в `public/images/logo/` и укажите `site.logo: "/images/logo/имя-файла.png"`. Пусто = демонстрационный герб фракции.
- **Фон обложки:** скопируйте изображение (рекомендуется 1600×800, WebP или JPG) в `public/images/backgrounds/` и укажите `appearance.backgroundImage`. Пусто = встроенная иллюстрация в цветах вашей палитры.
- Не используйте логотипы и иллюстрации Blizzard, не убедившись, что у вас есть на это права.

### 3. Добавить новость (меньше чем за минуту)

Создайте `src/content/news/zagolovok-novosti.md`. Имя файла станет адресом страницы: используйте только строчные латинские буквы, цифры и дефисы.

```md
---
title: "Заголовок новости"
description: "Одно предложение с кратким содержанием."
pubDate: 2026-11-04
author: "Имя"
category: "Объявления"
tags:
  - community
---

Текст новости в **Markdown**.

## Подзаголовок

- Маркированный
- список
```

Необязательные поля: `cover: "/images/news/kartinka.webp"` вместе с `coverAlt: "описание"`, `updatedDate`, `draft: true` (видно только в `npm run dev`, не публикуется).

В тексте используйте заголовки `##` и `###`: главный заголовок берётся из поля `title`.

### 4. Добавить руководство

Создайте `src/content/guides/imya-rukovodstva.md`:

```md
---
title: "Руководство по подземелью"
description: "Подготовка и тактика для группы."
pubDate: 2026-11-04
author: "Имя"
type: "dungeon"        # id категории из guides.categories
difficulty: "normal"   # необязательно: easy, normal, hard, heroic
featured: false        # true = рекомендуемое
tags:
  - dungeon
---

## Подготовка
...
```

Содержание руководства строится по заголовкам `##` и `###`. **Изображения** кладите в `public/images/guides/` и вставляйте так: `![Описание](/images/guides/karta.webp)`. Для **внутренних ссылок** используйте относительные пути (например, `[Состав](../../roster/)`) — они работают и на GitHub Pages.

У демонстрационных материалов стоит `example: true`, из-за чего показывается значок «Демонстрационный материал». Удалите их или замените своими.

### 5. Состав гильдии

Каждый участник в `src/data/roster.json`:

```json
{
  "id": "aldric",
  "name": "Aldric",
  "race": "Human",
  "class": "Paladin",
  "spec": "Protection",
  "role": "Tank",
  "rank": "Officer",
  "avatar": "/images/roster/aldric.webp",
  "description": "Короткий текст",
  "profileUrl": "https://...",
  "active": true
}
```

Обязательны `name`, `race`, `class` и `spec`, записанные как в каталоге (например, `"Night Elf"` или `"night-elf"`). Роль (`role`) по умолчанию определяется специализацией; `rank` должен входить в `guild.ranks`. Без `avatar` показываются инициалы. Недопустимое сочетание расы и класса вызывает ошибку с указанием участника и поля. Допустимые сочетания перечислены в [GAME-DATA.md](../GAME-DATA.md#raceclass-combinations).

Названия рас, классов и специализаций — английские игровые названия, одинаковые для всех языков шаблона.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Сервер разработки с автообновлением (показывает и черновики). |
| `npm run build` | Собирает статический сайт в `dist/`. |
| `npm run preview` | Локальный просмотр сборки. |
| `npm run check` | Проверки Astro и TypeScript. |
| `npm run check:config` | Проверяет настройки (`--strict` считает ошибками и предупреждения). |
| `npm run check:content` | Проверяет состав, новости, руководства и схемы frontmatter. |
| `npm run check:links` | После сборки: внутренние ссылки, указание авторства на каждой странице, отсутствие секретов. |
| `npm test` | Автотесты (контраст палитр, настройки, состав, каталог, темы, шрифты, переводы). |
| `npm run verify` | Всё перечисленное по порядку. |

Сообщения команд выводятся на английском и всегда указывают файл и поле, которые нужно исправить.

## Бесплатная публикация на GitHub Pages

1. Сделайте **форк** репозитория (или нажмите «Use this template»).
2. В **Settings → Pages** в поле **Source** выберите **GitHub Actions**.
3. Отправьте изменения в ветку `main` (можно просто отредактировать файл на сайте GitHub).
4. Workflow `.github/workflows/deploy.yml` устанавливает зависимости через `npm ci`, проверяет настройки и материалы, запускает проверки и тесты, собирает сайт, проверяет ссылки и указание авторства и **только если всё прошло успешно** публикует его по адресу `https://<пользователь>.github.io/<репозиторий>/`.

Никакие секреты не нужны. Адрес и базовый путь определяются автоматически: `site.url` используется только при локальной разработке и на других хостингах. Pull request'ы проверяются, но не публикуются.

### Без Git на своём компьютере

Всё можно сделать в браузере:

1. Сделайте форк и включите GitHub Pages, как описано выше.
2. Откройте файл (например, `src/config/site.config.mjs`), нажмите на значок карандаша, внесите изменения и нажмите **Commit changes**.
3. Для новости: откройте `src/content/news/`, выберите **Add file → Create new file**, вставьте шаблон выше и сохраните.
4. Для изображений: откройте `public/images/...` и выберите **Add file → Upload files**.
5. Через пару минут сайт обновится. Если что-то не так, на вкладке **Actions** будет видно, какой шаг не прошёл и какое поле нужно исправить, а опубликованный сайт останется в прежней версии.

### Другие бесплатные статические хостинги

`npm run build` создаёт папку `dist/` со статическими файлами, которую может отдавать любой статический хостинг.

**Cloudflare Pages:** подключите репозиторий и задайте команду сборки `npm run build`, папку `dist`, переменную `NODE_VERSION=24` и переменную `SITE_URL` с итоговым адресом (например, `https://my-guild.pages.dev/`).

**Netlify:** те же настройки (команда `npm run build`, папка `dist`, переменная `SITE_URL`).

На корневом домене (например, `https://my-guild.ru/`) базовый путь автоматически становится `/`.

> Примечание: на GitHub Pages в репозитории проекта (`/<репозиторий>/`) файл `robots.txt` находится не в корне домена, и поисковые системы его не учитывают. Карта сайта остаётся доступной и связана с каждой страницей. С собственным доменом всё работает как обычно.

## Известные ограничения

- **API Blizzard:** не подключены. Они требуют серверных учётных данных, а документированных точек доступа для Forever найти не удалось. Состав ведётся вручную. Подробности (на английском) — в [BLIZZARD-API.md](../BLIZZARD-API.md).
- **Игровые данные:** названия специализаций (таланты в Forever переработаны) ещё требуют подтверждения. См. [GAME-DATA.md](../GAME-DATA.md).
- **Шрифты на своём сайте:** для их загрузки сборке нужен интернет. Без сети используйте `fontLoading: "system"`.
- **Один язык на сайт:** интерфейс работает на одном языке; у посетителей нет переключателя языка.
- **Нет онлайн-формы заявки:** набор ведёт к указанным контактам.
